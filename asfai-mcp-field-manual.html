01 / Overview

A contract for someone else’s AI.

ASFAI Education is a privacy-first evidence ledger, a public children’s skill map, and an MCP contract for a host AI. It is not the model, the LMS, or the student database.

Limitations & licensing

05 / Policy

Evidence and approval are not the same thing.

Two mastery paths, two human-in-the-loop paths. When this MCP is served through agents, checks the server omits become model-controlled claims.

New material from isolated clone
PATH A · recordLearningEvidence · asfai-assessment-0.2

asfai_evidence → record_learning

Implementation: src/lib/learner-workflow.ts.

Mastered gateRequirement
InteractionsAt least 3
Observed evidenceAt least 2
ConfidenceAt least 0.7
AssistanceNot substantial

This is count-only: it does not distinguish questions from demonstrations. artifactIds is always empty; assessor.type is hardcoded ai; objectiveState.level is written immediately from the payload. There is no unit test for this function (the tests directory has none).

Live probe · 2026-10-06: three “what is MLE?” questions, assistance none, confidence 0.99, objective mt_iFFKZd-Vgv returned level mastered. Accepted.
PATH B · recordLessonEvidence · asfai-lesson-assessment-0.1

asfai_evidence → record_lesson

Implementation: src/lib/lessons/evidence.ts; tested in tests/lessons/evidence.test.ts.

Mastered judgementRequirement
ObservationsAt least 3
Evidence typesAt least 2
IndependentAt least 1 with assistance none
Weak evidenceNot self-reflection or collaboration alone
ConfidenceAt least 0.7

The test rejects mastery from one observation. This path asks about evidence quality more explicitly than Path A.

Architecture principle: an event records what occurred; it does not by itself prove mastery. A tutor that supplied a solution should not treat the answer as independent evidence. Rules should be inspectable and versioned.
Agent-serving implication

Patch Path A before designing Silicus TA 3.0.

A model can satisfy the current counts with chat questions and write mastered. Silicus is a complementary, independent product and must refuse to call record_learning from a question—but the gateway must refuse too. Playground guardrails are local only; they do not repair the live endpoint.

HITL / approval gates

A boolean from a model is not a human.

Path 1 · classroom connector

create_assignment, export_work, and return_evaluation: confirmed defaults false; preview without mutation; confirmed: true only after the user approves that specific preview. Same pattern for sharing/revoking course grants, publishing/closing rooms, publishing/retiring quizzes, and publishing/retiring educator resources.

Path 2 · lesson tool gap

asfai_lesson action create_assignment in register-asfai-tools.ts has no confirmed field. If getLesson finds a published lesson, it mints an urn:uuid assignment immediately and returns persistence notice educator.

Observed behavior

prepare_publication returns a confirmation string (“An authenticated publisher must preview and explicitly commit this immutable package”) but does not gate the operation. Live probe: confirmed: true on lesson create_assignment minted an assignment UUID without a teacher preview.

A string that says “confirm” is not an approval gate. validate_outline with nextState: reviewed is not HITL either.
Required direction

For agent-served tools, bind commit to a preview token or previous preview id—not a free confirmed flag. Use the same preview-then-approve pattern as the classroom connector for lesson assignment minting.
