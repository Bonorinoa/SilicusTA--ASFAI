# Red team, Sprints 5 to 8 (2026-10-14)

Run by the orchestrator, not delegated: the DeepSeek V4 Flash runs died on an OpenRouter HTTP 402
(no credits). Method: write each attack as a test that asserts the SAFE behaviour, run it against the
code as it stood (that failure is the finding), fix, keep it as a regression test.
All of it is in `host/test/redteam.test.mjs`.

## Findings, all fixed

| # | Sev | Sprint | Finding | Fix |
|---|---|---|---|---|
| 1 | HIGH | 7 | SSRF: the URL guard let IPv6 spellings of private addresses through. The URL parser rewrites `https://[::ffff:127.0.0.1]/` to `[::ffff:7f00:1]` and `[::ffff:169.254.169.254]` (cloud metadata) to `[::ffff:a9fe:a9fe]`, and the old check only matched the dotted form. Also open: `[::127.0.0.1]`, NAT64 `64:ff9b::`, 6to4 `2002::`, site-local `fec0::`, and `localhost.` with a trailing dot. | IPv6 is now an allow-list: only global unicast (2000::/3) outside the transition and documentation ranges is public. That one rule refuses every spelling above. Unparseable is refused. Trailing dot and case are normalised. |
| 2 | HIGH | 4-8 | A worker that never answers froze the course: every request to a course runs behind one lock and the model call had no deadline. A hung model meant a dead course until restart. | `PlanWorker` has a deadline (`timeoutMs`, default 60 s) covering the body read; a hang is `WORKER_UNREACHABLE` and the lock is released. |
| 3 | MED | 3 | The same freeze via ASFAI: the MCP client had no deadline. | `AsfaiClient` deadline (`timeoutMs`, default 30 s) becomes `ASFAI_UNREACHABLE`; the course still works locally. |
| 4 | MED | 7 | Label spoofing: a model-authored proposal was labelled `from <material name>`, and a name (or a web page's own `<title>`) of "your answer" made it read exactly like the teacher's own words. | Materials-derived labels are always `from material: <name>`; the three labels reserved for the teacher's words cannot be produced from a material. |
| 5 | MED | 6 | A source could return 100,000 citations; `retrieveAll` had no total cap, so one source could bloat the prompt. | At most `limit` hits looked at per source and `limit` kept in total. |
| 6 | MED | 6 | The ontology file was read whole with no size or node cap. | 2 MB and 5,000-node caps; over either it is "no context", and `verify` says it did not check. |
| 7 | LOW | 6 | A citation ref with whitespace, a line break, brackets or nothing after the namespace was accepted, so the text shown to the model and the text matched could disagree. | Such refs are dropped at the door. |
| 8 | LOW | 5 | `outcomeSentences` split only on `\n`, and left control and bidi characters in. A teacher's own outcome containing U+2028 could start a new line in the drafting prompt (a forged `- <id>:` objective line). Teacher-authored, so low. | One rule, every Unicode line terminator splits; control and bidi characters become spaces. |
| 9 | LOW | 7 | yt-dlp read the machine's own config, which can add `--exec`. | `--ignore-config`. |

## Held up (tried, could not break)

- Prototype pollution through `__proto__` and `constructor` keys in an answer: nothing polluted, only the three known keys survive.
- Twenty parallel answers plus five parallel outline confirms on one course: the log still verifies.
- Local answers then ASFAI: the outline is not authorized while ASFAI's round is open, but one more teacher reply arms the round and the course recovers. No lock-out.
- A teacher turn with `outcomes_from` alone, wrong values (`true`, `"Materials"`, arrays, objects) or without topic and course authorizes nothing.
- The materials-propose body cannot inject an objective, source label, assistant turn or provenance.
- Material that tries to forge a material header or command the worker only changes what is proposed; nothing is accepted for the teacher.
- Student chat: cannot forge package lines, accepts no identity, reads only the sealed version, writes nothing (log head and ledger unchanged), and an unknown or traversal course id creates nothing on disk.
- Retrieved text and material text are in no log, export or data-directory file (full-directory scans).
- Citations cannot be promoted to objectives; they are not in the sealed package or the publish preview.

## Known residuals, not fixed

- DNS rebinding between the address check and the connect in the URL fetcher (documented; the host is loopback-only and the teacher supplies the URL).
- Student chat has no rate limit, and each question replays and verifies the course log. Fine on loopback; add a limit before any hosted deployment.
- The model's student answer text is not content-filtered beyond the citation requirement: a model could still phrase something it should not (for example a mastery claim). The prompt forbids it and nothing is recorded, but it is not enforced.
- The log is tamper-evident, not tamper-proof (unchanged).
