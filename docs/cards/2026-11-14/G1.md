## What to build

1. **A pinned, trimmed snapshot.** A script (for example `host/scripts/marble-snapshot.mjs`) downloads both files at
   the pinned commit, checks their sha256 against what it downloaded before writing, keeps only the fields the app
   uses (`id, type, subject, domain, name, description, evidence, ageRangeStart, ageRangeEnd` and the four edge
   fields), and writes **one** JSON file both hosts can load, served as a static asset by the frontend build. It
   records the source commit and file hashes inside the file. Report its raw and gzip size. Add an ODbL attribution
   notice next to it and a line in the app's about/credits area if one exists ("Contains information from the Marble
   Skill Taxonomy, made available under the Open Database License v1.0").
2. **A pure graph module** with no network: `search(query, {ageMin, ageMax, limit})` (plain lexical scoring over
   name, description and evidence; no embeddings, no model call), `get(id)`, `prerequisites(id)` → hard and soft with
   reason, `dependents(id)`.
3. **A `MarbleSource extends KnowledgeSource`** (`host/knowledge.mjs` defines the contract). `id "marble"`, namespace
   `marble`, `egress null` (nothing leaves the device), `canVerify true` (membership in the snapshot). Label carries
   the age range the way `host/sources/asfai-graph.mjs:74-78` does. **Grain guard:** when the course audience is
   entirely outside 3 to 15, or no hit overlaps the audience ages, return nothing. A query for "maximum likelihood"
   for a 19-year-old course must return no citation.
4. **Wire it into both hosts.** Node: `host/server.mjs:132` list (disable with `SILICUS_SOURCE_MARBLE=0`). Browser:
   `browserHost.ts` sources, loading the snapshot lazily. `GET /api/knowledge/status` then lists `marble` enabled in both.
5. **Two read-only routes in `host/handler.mjs`** (so both hosts get them): search (query, ages, limit) and topic by id
   with its prerequisites and dependents. They write nothing to the course log. A later card (G2) builds the studio
   UI on these, so return a small, stable JSON shape and document it in `host/README.md`.
