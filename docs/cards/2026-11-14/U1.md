# U1 · CORS allow-list for browser MCP clients, on a fork of asfai-education

## Why

asfai-education issue #16 (`gh issue view 16 -R redbeard-26/asfai-education`) describes why a browser-only MCP
client such as Silicus's online app cannot complete OAuth or call `/api/mcp`, and proposes the exact behaviour. The
issue offered a PR "once you confirm the shape". We now prepare that PR so Michael (maintainer) only has to review
and merge it. **Silicus does not depend on it for December** (G1 reads Marble directly); it is the path to
"Connect ASFAI" in the online app later.

## What to build (follow the issue's "Proposed behavior" exactly)

- Fork: `gh repo fork redbeard-26/asfai-education --clone=false` (account Bonorinoa). Clone the fork to
  `/Users/bonorinoa/Hermes/Projects/asfai-education-fork`, add `upstream`, branch `fix/cors-browser-mcp-clients`
  from `upstream/main`. Record the upstream sha you started from.
- `ASFAI_CORS_ORIGINS` env var, comma-separated exact origins. **Unset means byte-identical to today.**
- For a listed `Origin`: echo it, `Vary: Origin`, the methods, allowed headers, exposed headers and max-age listed in
  the issue. No `Access-Control-Allow-Credentials`.
- `OPTIONS` handlers on `src/app/oauth/register/route.ts`, `src/app/oauth/token/route.ts`, the revoke route, and
  `src/app/api/[transport]/route.ts`. CORS headers on the real responses too, including the 401 from `/api/mcp`
  (its `www-authenticate` must be readable).
- One small shared helper, not copies in four files. Respect the app's `basePath` (`/education`).

## Acceptance

- **Tests first.** A failing test for each endpoint (preflight, listed vs unlisted origin, exact header set, env unset
  = no headers), shown failing on the upstream sha, then passing.
- The repo's own checks on Node 22 exit 0: `npm ci`, `npm test`, lint, `next build`, and the plugin build and smoke
  if the repo has them. Name each command.

  worktree, branch `docs/upstream-cors`): what changed, how to test with one `curl` per endpoint, the two open
  questions from the issue with our recommended answers, and "additive, default unchanged".
- Branch pushed **to the fork only**. Do **not** open the PR. Do not comment on the issue.
